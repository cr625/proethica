## Question 2. Behaviour the rules do not name

### Fixed on the review branch

1. **A table name became the ontology target.** `app/services/entity/unified_entity_resolver.py`, `_ontserve_row_source` (line 262) and the inventory loop (line 227). The OntServe inventory (`storage/concept_manager.py`, `get_entities_by_category`) returns concepts-table rows with `source: 'concepts'` and ontology rows with `source: <ontology name>`, written as `'ontology'` when the name is missing. The branch took the field as the declaring ontology, so an approved concept received `ontology_target 'concepts'` and the popover link `/entity/concepts/<fragment>`, a page OntServe does not serve; the base gave every row `proethica-intermediate`. Fix: the two table values count as no name, and such a row takes the target of its URI namespace (`_derive_ontology_target`), then `proethica-intermediate`. Tests: `TestInventorySourceField` (three tests, two of them parametrized).

2. **Ties between definitional ontologies followed the row order.** Same file, `_ontserve_row_rank` (line 272). Two definitional ontologies that both describe one URI ranked equal and the first inventory row won. The class commit refuses base copies into the extended store only since the D15 rule (`app/services/commit/class_commit.py`), so a class declared by `proethica-intermediate` and by `proethica-intermediate-extended` is a live case, and the inventory query orders by label over `SELECT DISTINCT`, so the definition and the OntServe link of such a class depended on which row came first. Fix: the rank gains a third element, whether the row's ontology owns the URI namespace, so `proethica-intermediate` wins an intermediate URI over the extended copy in either order; a described copy still outranks an undescribed owner. `test_rank_helper` in the branch's test file follows the tuple. Tests: `TestDefinitionalTie` (three tests, one parametrized; at the cluster tip the `reverse=False` case fails and the `reverse=True` case passes by order).

3. **The step 5 page ran the scanner without the alias actors.** `app/templates/scenario_pipeline/step5_traversal.html` (line 212). The page feeds the same `scanTextForEntities` as the case page, and its lookup serialization carried `aliasTypes` and `aliasEntities` only, so `entity.aliasActors` was undefined there and an alias such as "faithful agent" was decorated in every sentence of the decision text while the resolver had already restricted its grounding. Fix: the template serializes `aliasActors` as `case_detail.html` does. Tests: `TestLookupSerialization`.

4. **The mirror was tied to the JavaScript by string matching only.** Test change. `tests/unit/test_annotation_layer_review.py::TestMirrorAgainstNode` runs `buildEntityPattern`, `sentenceWindow`, `aliasActorPresent`, `truncateDefinition` and `splitAgentFacets` under node (a `vm` context with a stub `document`) on 213 pattern texts, 18 sentence windows, 14 actor checks, 11 truncations and 11 facet splits, and compares each result with the mirror; it is skipped where node is absent. A wider one-off run over the integration tip (676 inputs, 608 of them pattern texts over the fixture keys in fifteen contexts) found no difference.

### Reported, not changed

5. **Aliases of entities without an actor.** `unified_entity_resolver.py`, `_phrase_grounded` (line 576). An entity whose label names no actor (a State, Principle, Resource or Constraint without a leading designator, such as "Public Safety Faithful Agent Conflict" or "Confirmed Runoff Risk Finding") grounds a sub-phrase only through a reference equal to the phrase; on the base any reference containing the phrase grounded it. An alias that only such entities supported (two of them across two types, "runoff risk" from a State and a Principle for instance) no longer exists on any page, and such entities no longer join the contributor list of an alias that actor-bound entities carry. The commit message names the rule and the branch fixture asserts the conflict state is not a contributor, so this is a choice. Proposed: record the decision, or keep the any-reference rule for an entity without an actor when no actor-bound entity shares the phrase, which leaves `alias_actors` empty and the scanner gate off for that alias.

6. **The designator pattern accepts any capitalized word followed by one letter.** Same file, `_ACTOR_DESIGNATOR` (line 73), first alternative. "Canon I.4 Faithful Agent Obligation" yields the actor "Canon I" (the letter is followed by a period), "Plan B Adoption" yields "Plan B". Grounding then requires the reference sentence to contain that opening, and the scanner decorates the alias only in sentences that contain it. Proposed: exclude the period from the character after the letter, and consider restricting the first alternative to role nouns.

7. **Sentence splitting at abbreviations.** Same file, `_reference_sentences` (line 568), and `app/static/js/ontology-popovers.js`, `sentenceWindow` (line 332). Both split after a period followed by whitespace, so "Engineer L, P.E. acted as a faithful agent" and "Mr. Smith, Dr. Jones and Engineer L: a faithful agent?" split before the alias, the sentence that holds it lacks the actor, and the alias is neither grounded nor decorated there. The two sides agree (the node run covers these inputs). Proposed: treat a period after a single capital letter or a known abbreviation as non-terminal, on both sides.

8. **The server-side annotator applies the old rules to the same index.** `app/services/annotation/text_annotator.py`, `_build_sorted_labels` (line 84), `_compile_pattern` (line 93), `annotate` (line 100). It filters case labels by `SKIP_WORDS` and `MIN_LABEL_LENGTH`, keeps the trailing `\b` (so the `iii.1.b.` key never matches while the bare key does) and ignores `alias_actors`. Reached through `app/routes/annotations.py` (line 356); the `annotate_entities` template filter (`app/template_filters.py`, line 333) has no template user. Proposed: give it the scanner rules (lookahead, case-key bypass, actor gate), or mark the surface legacy.

9. **Ties among non-definitional ontologies still follow the row order.** `_ontserve_row_rank`: `owns_namespace` is false for every namespace without a pattern in `_URI_ONTOLOGY_PATTERNS` (`engineering-ethics`, `core`), so two domain ontologies describing one URI keep the first row. No such pair is known in the clone.

10. **The target of engineering-ethics rows changed.** The base linked every inventory row to `/entity/proethica-intermediate/...`; the branch links a row to its declaring ontology, so engineering-ethics classes now point at `/entity/engineering-ethics/<fragment>`. This is the rule; it assumes the OntServe ontology is named as the inventory reports it.

11. **A wrapped citation anchor fires the delegated navigation event.** `ontology-popovers.js`, the `click` listener at the end of the file dispatches `entity-navigate` for any `.onto-label` ancestor of the click target, so a click on a cited-case link inside the wrapper fires it before the browser follows the href; only `step4_review.js` listens, and the case page has no listener. The dotted underline of the wrapper also stacks on the link underline. Cosmetic.

### Checked and found consistent

- The Structure card when OntServe is unreachable (`app/routes/document_structure/view_routes.py`, `term_links_context`, line 26). `committed_case_exists` is a file check under `get_ontserve_base_path()`; a missing `ONTSERVE_BASE_PATH` raises and the context catches it, an unmounted directory returns False, and either way the card shows and the rows load. `view_case` gates the popovers on the same predicate, so the two surfaces fall back together (legacy card, no popovers), and the term-links query runs only when the card renders.
- The listing after `has_term_links` was removed. No template reads the flag apart from `document_structure.html`, which the structure route still feeds through `term_links_context`.
- The merged `view_case` (`app/routes/cases/view.py`). The merge kept the import of `get_entities_summary` from `app/services/step4_synthesis/step4_data_helpers.py` and the retrieval-features `load_latest_transformation` (`app/services/case_analysis/transformation_classifier.py`), both present, dropped the term-links block and its template argument; `case_detail.html` never read `term_links_by_section`. The other eight cluster files are identical at the cluster tip and the integration tip.
- The lookahead at the end of a text node. `(?![A-Za-z0-9_])` succeeds at the end of the input, fails before a word character (`III.1.b.5`, `Case 76-45`, "faithful agents"), and the two sides agree on 608 texts. A key with a trailing period swallows the sentence period when the text writes the label without it ("requires III.1.b." decorates `III.1.b.`); the span then shows the label as declared.
- The alias gate on the scanner side for an alias without actors: `aliasActorPresent(sentence, [])` returns true, so such an alias is decorated everywhere, as before.
- A real-DOM run of `scanTextForEntities` with the case page options (headless Chromium through Playwright, a one-off script, not committed) over a case-shaped fixture: provision keys match with and without the period; `Case 84-5` and `BER Case 76-4` anchors are wrapped with their href intact and `data-entity-anchor` set, an anchor whose text is mostly something else and an anchor inside a `.badge` are left alone; a sentence split by `<em>` is seen whole, so the alias after the element links; the Engineer Doe recap and a sentence with no actor stay unlinked; the NSPE references card is untouched; "faithful agents" is unmatched; `NSPE Code of Ethics` is decorated beside an undecorated `Code of Ethics` and `State`, and `DP1` is decorated. `buildPopoverContent` renders the Agent definition as a lead and seven facets, the alias as a two-entry contributor list and the provision with its definition.
- `_PLACEHOLDER_DESCRIPTION` matches the text OntServe substitutes (`f'Ontology class for {category}'`, `concept_manager.py` line 660).
- `app/static/js/case_detail.js` keeps `highlightTermsInSection`, which nothing calls, and nothing reads `window.termLinksData`.
- `ontology-popovers.js`, `cases/case_detail_page.js` and `scenario_pipeline/step5_traversal.js` pass `node --check`.
