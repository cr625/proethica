## Question 2. Behaviour the rules do not name

### Fixed on the review branch

1. **Duplicate tensions from the competing-obligation branch (introduced by the merge).** `app/services/narrative/narrative_element_extractor.py`, `_extract_conflicts` (line 649), the `if obligation_label and competing_label` branch (line 676). The step4-synthesis merge placed its branch for the committed competesWith pair (lesson L4 of that cluster) ahead of the pair dedup this branch added to the constraint-slot branch (L5), and the new branch neither checked nor registered the pair. Scenario: a phase 4 run from stored rows once `CanonicalDecisionPoint.from_storage` (step4-synthesis review, commit 824c79d) restores `competing_obligation_uri` and `competing_obligation_label`. Case 8 DP2 and DP3 both carry Watershed Safety Duty against Faithful Agent Duty and produced the exact duplicate D-41 names (conflict_3), and the heuristic branch could repeat the pair as a "Potential tension" entry. Fix: the branch keys the pair with `_pair_key` and skips a seen pair, as the other two branches do. Tests: `TestCompetingPairDedup` (four).

2. **Non-polar board conclusion types replaced the text classification with 'unclear'.** `app/services/precedent/case_feature_extractor.py`, `board_outcome_for_case` (line 142). `_detect_board_conclusion_type` (`conclusion_analyzer.py`, line 386) returns 'unknown' when no pattern matches, and 'interpretation' or 'recommendation' for holdings without a verdict; the TTL emitter already skips 'unknown'. For a case whose board_explicit rows carry only such values the derivation returned ('unclear', 0.0), `extract_outcome_for_case` (line 440) wrote it over the regex result at feature extraction, and `_refresh_outcome_from_board_conclusions` (`phase4_connector.py`, line 129) overwrote the stored outcome on every phase 4 run, after which outcome_alignment scored 0.5 against every case that is not itself 'unclear'. The rule names the conclusion-text regex as the fallback for a case without typed board conclusions, and a case whose typed conclusions carry no verdict is such a case. Fix: `board_outcome_for_case` returns None unless a polar value (no_violation, compliance, violation, mixed) is present; `derive_outcome_from_board_conclusions` keeps its 'unclear' result for a direct call. Tests: `TestNonPolarBoardTypesKeepTheTextOutcome` (four).

### Reported, not changed

3. **Two predicates classify the legacy positional conclusion keys differently.** `narrative_element_extractor.py`: `is_board_explicit_conclusion_uri` (line 45, this branch) returns False for a positional key such as `case-8#C2`; `_is_board_conclusion_uri` (line 55, step4-synthesis) returns True for it. In the merged `_extract_decision_moments` (line 814) a point aligned to a positional key gets `has_board_conclusion` True and `board_choice` None, so the scenario generator authors a board_rationale for a branch that shows no Board choice. The two branches chose opposite defaults on purpose (the docstrings say so). Proposed: one predicate for both flags, once it is decided whether positional keys count as the Board's.

4. **The model path has no production caller.** `llm_extract_features` (line 486) is called nowhere in `app/`; the step-0 `precedent_features` extraction_prompts row and the board override of the model outcome exist only through the tests. The outcome written in production comes from `extract_outcome_for_case` at ingestion and from the connector refresh. Proposed: none for this review; wire the call or retire the path when the Haiku feature extraction is next used.

5. **transformation_pattern is reset and never refreshed.** `_clear_step4_data` (`step4_synthesis_service.py`, line 363) now resets `transformation_pattern` with the other Step 4 columns, and the connector writes `transformation_type` only (line 72). The one writer of the pattern is `save_features` through `_get_step4_data` (line 828), which runs at ingestion. After a Step 4 re-run the column stays None until the features are extracted again. The column is not weighted. Proposed: the connector reads the pattern from `load_latest_transformation` beside the type.

6. **Tag sources differ per case and per page.** `resolve_subject_tags` (`similarity_service.py`, line 28) falls back to the model-assigned column when a document carries no `doc_metadata.subject_tags`, so a pair can be scored NSPE references against model tags; the network tag filter (`similarity_routes.py`, lines 47 and 68) and deep search (`deep_search_service.py`, line 62) read the column. The D-42 corpus-wide correction (`subject_tags := doc_metadata.subject_tags`) makes the sources agree; until then the fallback is the one the rule names.

7. **entity_classes from an appended committed graph.** `_commit_individuals_to_case_ontology` (`ontserve_commit_service.py`, line 511) loads the existing case TTL and adds to it, so a case re-extracted and re-committed through this path keeps the individuals of the earlier run, and their classes now count in `entity_classes` (`derive_entity_classes`, `precedent_features.py` line 95), where the working-store derivation counted the published rows only. The versioned path (`commit_case_versioned`, `_write_case_ttl_fresh`) overwrites. The rule names the committed graph as the source; noted for the commit-stage reviews.

### Checked and found consistent

- Every write of `provisions_cited` passes through `normalize_provision_codes`: `extract_provisions`, `save_features` (line 660), the Haiku validator and `update_provisions_cited`. No other writer exists in `app/` (`cited_case_ingestor` creates the row empty, `reset_step4_case_features` leaves the column). `_calculate_provision_overlap` (line 548) and `_get_matching_provisions` (`helpers.py`, line 198) compare normalized sets; `deep_search_service` lowercases both sides; the `experiments/` scripts compare their own exports. The empty-side return of the overlap is evaluated after normalization, so a value that normalizes to nothing no longer dilutes the union; no stored row carries one, since every writer normalized or filtered.
- tag_overlap: `_get_case_features` (line 426) joins `documents` and resolves the document tags before the column; the Jaccard and `matching_tags` use the one resolved set; `_find_precedents_for_case` displays `match.matching_tags`.
- `extract_outcome` (line 313): "not unethical" and "not be unethical" are removed before the bare-word search and score the ethical side; "was not ethical" and "would not be ethical" keep the unethical side; a bare "unethical" scores as before.
- `load_latest_transformation` on a `raw_response` that is a dict: `_parse_transformation_record` (`transformation_classifier.py`, line 649) would raise AttributeError on `.strip()`, and every caller catches it (`_resolve_transformation_type` returns the column value, `_get_step4_data` and the case page log a warning). The column is `db.Text` and every writer stores text (`classifier.last_response`, `json.dumps`), so no stored row is a dict.
- `update_entity_classes_from_storage` runs after the TTL write in `commit_selected_entities` (`ontserve_commit_service.py`, line 400), so the graph it reads is the one just written. Against the golden TTL the derivation groups the role, state and obligation individuals under their direct core category with their intermediate classes, skips the analysis-layer individuals (EthicalQuestion, EthicalConclusion, DecisionPoint) and the core:Agent individuals, and emits no key for the bare core:Action individual. The origin subclass the emitter asserts beside core:Event (core:ExogenousEvent) is skipped as a core-namespace type; the working-store derivation never carried it (temporal rows have no `types`), so the shape is unchanged. The two sources key temporal rows differently ('temporal' from the working store, 'action' and 'event' from the graph); `matching_ops.calculate_jaccard` unions every URI regardless of key.
- The four callers of the connector (`phase4.py` twice, `complete_synthesis.py`, `_run_narrative`) pass the latest `transformation_classification` record, so the always-write replaces the column with the current classification; the service clear now calls `reset_step4_case_features` as the route clear does.
- `is_board_explicit_conclusion_uri` gates `board_choice`; `_extract_obligation_conflicts` (line 205) drops empty slots for the dataclass and the dict shape; `conflict_type` is consumed as free text (`insight_deriver`, `narrative_view`, `interactive_scenario_service`), so the typed `<type1>_vs_<type2>` forms need no mapping.
- The storage-persistence connector test (`test_phase4_connector_rewrites_metadata_on_rerun`) patches `board_outcome_for_case`, so the refresh is inert there. It fails when run alone, because the `patch.object` call in that test on `CasePrecedentFeatures.query` needs the application context another test in the file pushes, and it passes with its file, before and after the fixes.
