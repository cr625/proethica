## Question 2. Behaviour the rules do not name

### Fixed on the review branch

1. **The candidate pool was narrowed across the descriptions of one class row.** `app/services/extraction/state_edges.py`, `_collect` (line 501). The pool restricted for one `obligation_activation` entry (to the obligations citing the code it names when several do, or to the lexical candidates of a duty name) stayed restricted for the next entry of the same class row, since `pool` was bound once outside the loop. Scenario: a class row naming two duties with individuals ("Duty to Protect Public Safety", "Faithful Agent Duty"); the second was shortlisted against the candidates of the first and resolved to nothing. Case 8 class row 95600 names three duties, so the correction of D-28 (two activatesObligation edges from the conflict state) could not have been produced by the applier. Fix: the pool is taken from `pools[prop]` per description. Test: `test_second_duty_name_on_one_class_row_resolves`.

2. **The committed description was never read.** `app/services/extraction/edge_coherence.py`, `happening_occurred` (line 322) and `later_happening_citing_state` (line 504) read `proeth:description`, while `ttl_emitters._add_temporal_fields` (line 854) writes the description of a temporal individual as `rdfs:comment`. Scenario: every committed graph. The Allen endpoint check saw only the temporal marker and the section (Refusal_to_Acquiesce stayed prescribed through "unresolved endpoint" in its marker; an action prescribed only in its description counted as performed), and the termination check matched labels only. Fix: `happening_description` reads `rdfs:comment` first and the `proeth:description` literal second; both checks use it. Tests: `test_happening_occurred_reads_the_committed_description`, `test_later_happening_citing_state_reads_the_committed_description`, both through the real converter and emitter.

3. **The two modality derivations disagreed.** prompts-and-filters stores `proeth:modality` on every action row at parse time (`happening_checks.classify_action_modality`, from the verdict of the model and the Board-normative text references) and the emitter commits it as a literal. This cluster derived the modality again from phrases in `edge_spec._demote_prescribed_fulfills` (line 1244), `obligation_engagement_apply.apply_obligation_engagement` (line 232) and `edge_coherence.happening_occurred`, ignoring the stored value. Scenario: an action whose Board sentence sits in its text references and whose description is neutral ("Engineer L declines to continue the design work") is prescribed at parse time and performed here, so its fulfills edges survived; a discussion-section action whose description says "would" is performed at parse time and prescribed here, so its fulfills edges were demoted. Fix: `derive_action_modality` takes `explicit` and returns a stored value of `performed` or `prescribed` as it stands; the three callers pass the stored literal; the phrase rule stays for rows that carry none. Tests: `test_stored_modality_wins_over_the_phrase_rule`, `test_committed_modality_literal_decides_happening_occurred`, `test_row_adjust_honours_the_stored_modality`, `test_engagement_pass_honours_the_stored_modality`.

4. **A fluent label a State carries was rejected when a happening shares it.** `app/services/extraction/edge_spec.py`, the `reject_labels` block (line 554). Scenario: a State and an Action both labelled "Work Suspension", and an initiates label "Work Suspension" on another happening; the label was rejected as a happening label although the pool holds a State with that label. Fix: labels of pool members are removed from the rejection set (line 560). Test: `test_fluent_label_shared_by_a_state_and_a_happening_resolves_to_the_state` (the Event-label case of lesson L3 still rejects).

### Reported, not changed

5. **The causal order is absent when the relation family validates.** `app/services/extraction/edge_materialization.py` runs `temporal_relation_edges` (line 236) before `apply_causal_edges` (line 256) and `apply_event_cause_edges` (line 268), and `edge_coherence.precedence_graph` (line 369) reads the `proeth:cause`, `proeth:effect` and `proeth:causedByAction` object edges those appliers emit (the converter stores the chain endpoints as labels, so the emitter writes `causeText`). On the first materialization of a run the precedence graph holds the temporalSequence order only; the branch test passes because its fixture graph carries the chain edges. The D-17 relation (the risk before the study) is still caught through the sequence when both endpoints are sequenced. Proposed: run the relation family after the causal appliers, or build the precedence graph from the CausalChain rows.

6. **A met obligation with no text references is restored for every action.** `app/services/extraction/obligation_engagement_apply.py`, `_refs_cite_action` (line 104). The rule names a met obligation whose text references cite the action; with no references the function returns True, so any action whose input pool listed the obligation under fulfills keeps it there whatever the model answered, including an action that merely raised it. Deliberate in the branch test ("no refs: the met judgment stands"). Proposed: with no references, follow the model, or restore only when the obligation appears in the fulfills of exactly one action.

7. **The deontic heuristic for discussion-section rows is broad.** `edge_coherence._DEONTIC` (line 275) matches `would`, `may not`, `required to` and `should` anywhere in the description or marker. With finding 3 it applies to rows that carry no stored modality (every row extracted before the field, case 8 among them); for those, a discussion-section action narrated with such a word ("notified Client X, as required to by III.1.b") becomes prescribed and loses its fulfills edges. This is the second point section 6.2 flags. Proposed: use the `BOARD_NORMATIVE_RE` of `happening_checks` for the legacy rows so both derivations apply one pattern, or drop `would` and `required to`.

8. **The verbatim-evidence check is character-exact.** `edge_coherence.evidence_is_verbatim` (line 353) delegates to `causal_extractor._check_quote_grounding`, which normalizes whitespace and case only. `_load_case_text` (edge_spec line 1271) reads `document_sections.content`, the same source the other present-case loaders read, and the model quotes from `sections_dual.text`; a typographic apostrophe or quotation mark in either side withdraws the relation (both endpoint edges and the time triple). Proposed: the token-level test of `quote_grounding` (punctuation-insensitive, used by the verification gate), which still rejects the D-16 hedge.

9. **A later mention of a state blocks its termination.** `edge_coherence.later_happening_citing_state` (line 504) drops a termination when the label or description of any later happening shares 60 percent of the content tokens of the state label (`cites_state`, line 254). A retrospective mention ("after the budget constraint ended") blocks the termination as well as a continuing one. Proposed: require the state label in full, or a present-tense cue.

10. **A lone code in a prose source still yields establishedBy.** `app/services/extraction/provision_citation_resolver.py`, `apply_established_by_edges` (lines 225 to 230). Rows without the new `establishing_provision` field (every row extracted before this branch) take the edge from a source that resolves to exactly one code. A source naming only the bounded canon ("NSPE Code of Ethics, Canon I.4") produces establishedBy I.4. This is the first point section 6.2 flags; the branch chose it so legacy rows keep an edge. Proposed: keep, and record the source of the edge in the result (`from_source_literal`) so a replay can list them.

11. **The participant scaffold reads a literal no code writes.** `app/services/extraction/edge_spec.py`, `_action_modality` (line 367, from commit-definitions) checks `proeth:actionModality`; the stored and committed literal is `proeth:modality`. The scaffold then falls to its four-phrase list (`_PRESCRIBED_MARKERS`, line 363), a third derivation beside the two of finding 3. Belongs to the commit-definitions review; noted here because the file is shared. Proposed: read `proeth:modality` and delegate to `edge_coherence.derive_action_modality`.

12. **The Action pool reads a description the graph does not carry.** `edge_resolution._candidate_pool` (line 110) builds the happening pool for the state family from the label plus `proeth:description`; on the committed graph the text is the label alone (the Event pool had the same limitation before the branch). Proposed: `happening_description` in `_lit`.

13. **Minor.** `edge_coherence.named_target_bound` (line 223) splits a single label on "and", so "Health and Safety Obligation" bounds a select to two targets (lenient, never restrictive). `reconstruct_edge_family` (edge_spec line 807) has no caller outside the tests; the replay scripts are local. `proeth:establishingProvision` and `proeth:modality` are undeclared in `proethica-intermediate.ttl`, so the shapes and the reasoner ignore them.
