## Question 2. Behaviour the rules do not name

### Fixed on the review branch

1. **The working store honored the match at any confidence, so the L4 floor never acted on a new row.** `app/services/extraction/extraction_graph.py`, `individual_type_iri` (line 293, from the storage-persistence branch) returned the matched IRI whenever `matches_existing` carried a full URI. Scenario: a specialization "matched to parent with medium confidence" (the prompt's 0.70 to 0.85 band). The row reached the commit with `rdf_json_ld.types` already naming the parent; `_matched_class_override` (`category_resolution.py` line 194) saw the matched class among the minted types and returned None, so the writer typed the individual to the parent and both stores agreed on the class the floor was meant to refuse. The minted specialization was lost. Fix: the store applies `match_policy.match_link_threshold` (the same default and the same `PROETHICA_MATCH_LINK_THRESHOLD` override); below it the minted IRI stands in both stores, at or above it the two rules agree. The storage-persistence suite passes unchanged (its fixtures link at 0.9 and 0.95). Tests: `test_store_type_follows_the_match_only_at_the_link_threshold`, `test_stored_row_and_commit_name_the_same_class_on_both_sides_of_the_floor` (the row as `pydantic_to_rdf_data` writes it, then the override).

2. **The participant scaffold read a modality literal nothing writes and classified with its own marker list.** `app/services/extraction/edge_spec.py`, `_action_modality` (line 371). The temporal converter stores the model's call as `proeth:modality` (`rdf_converter.py` line 208) and `_add_temporal_fields` copies the key verbatim; the scaffold read `proeth:actionModality`, so the stored call never reached it and every action fell to the marker scan, whose four markers are a subset of `edge_coherence.PRESCRIBED_PHRASES` (twelve phrases plus the deontic rule for discussion-section actions) that `obligation_engagement_apply.py` applies to the same actions. Scenario: an action described as "is not permitted to continue", or a deontic Board sentence from the discussion, was prescribed to the engagement pass and performed to the agent definition. Fix: `_action_modality` reads `proeth:modality` (and `actionModality` for graphs that carry it) and falls back to `derive_action_modality` over the comment, the temporal marker and `discoveredInSection`, as `happening_occurred` does. Tests: `test_scaffold_reads_the_stored_modality_literal`, `test_scaffold_fallback_agrees_with_the_engagement_classifier`.

3. **The gate read the link confidence from a column the storage fills for declined matches too.** `app/services/extraction/verification_gate.py`, `match_confidence_of` (line 319). `rdf_storage_service.py` writes `match_confidence` from `match_decision.confidence` whether or not the decision linked the row (lines 139 and 188), and the function preferred the column. Scenario: a decision `matches_existing` false with a confidence and a `matched_uri` label (the one shape the matcher's cleanup does not zero); the row read as linked at that confidence and, with verbatim quotes, `_linked_verbatim` left it unjudged by the grounding and over-reach passes. Fix: a recorded decision that did not link the row yields None; a linked row keeps the column preference; a row without a recorded decision reads the column as before. Test: `test_gate_link_confidence_follows_the_recorded_decision`.

4. **A duty toward a named party was rerouted to the public counterparty.** `app/services/commit/ontserve_commit_service.py`, `_REL_TYPE_TO_PROP` (line 1136). The branch added two needles for the public duty, `owes_duty_toward` and the generic stem `duty_toward`; `_rel_property_for` matches needles as substrings of the normalized type, and both the controlled `relationships` path (`ttl_emitters.py` line 518) and the overflow path (line 591) convert any match into an `owesDutyToward` edge to the case-scoped `PublicInterest` individual, with the target label kept as its `skos:altLabel`. Scenario: an overflow entry `{type: "has fiduciary duty toward", target: "Client X"}`, which the base staged as a literal, minted "General public" with the alias "Client X", typed the facet PublicResponsibilityRole and recorded a derivation. Fix: the generic stem is removed; `owesDutyToward` and "owes duty toward" still route. Test: `test_a_duty_toward_a_client_stays_a_staged_literal`.

### Reported, not changed

5. **The declined-accumulation rule keys on a decision shape the stored record does not have.** `app/services/commit/class_commit.py`, line 135. The rule skips the accumulate path when `matches_existing` is false and `matched_uri` names the existing class. The D-22 record is a positive match to LegalObligation at 0.75 under a label canonicalization rewrote to RegulatoryComplianceObligation; for that row `linked_existing_class` returns None (below the threshold), the class exists, and the accumulate path appends the case context as before. The merge-guards branch now blocks the rewrite upstream, so the recurrence is prevented there, not here. Proposed: skip accumulation when the decision names a different class and the row's canonicalization metadata records a rewritten label, or document that the rule relies on merge-guards.

6. **The publish guard refuses individuals of pending class rows, not only of rejected ones.** `app/services/commit/publish_guard.py`, `unpublished_class_keys` (line 57), and `ontserve_commit_service.py`, `_unpublished_class_keys` (line 498). The query keys on `is_published` false; a class row that is selected and merely outside the batch counts like a gate-dropped or deselected one. Every production caller commits the selected unpublished rows of the case together (`entity_mgmt.py` line 155, `reconciliation.py` line 403, `pipeline_tasks.py` line 1296), so only an explicit partial `entity_ids` request reaches the case. Proposed: refuse on `is_selected` false (the durable drop marker and the review deselect) or pull the pending class rows into the batch.

7. **PublicInterest is typed to its class, not to `core:Agent` directly.** `app/services/commit/ttl_emitters.py`, `_ensure_public_interest` (line 690). Deliberate and documented (the one-hop actor pools of the edge appliers stay unchanged), and `proeth:PublicInterest` is `rdfs:subClassOf core:Agent` in the intermediate tier, so the reasoner infers the type. The D-11 correction wanted a community agent and D-31 wants `affects` edges from four states to it; the state-affects applier draws its candidates from the direct Agent pool and cannot reach this individual. Reported as a design choice.

8. **Every intermediate class ending in Role outside the five relational archetypes counts as occupational.** `app/services/commit/agent_layer.py`, `_carry_occupational_type_to_relational_facets` (line 73). Participant heads (PublicRole, ClientRole) and abstract heads (ProfessionalRole, ParticipantRole, EngineerRole) satisfy the test, so an agent whose only other facet carries such a head carries it onto its relational facets. Low impact, since the role individuals are typed to leaf classes in practice. Proposed: restrict the carried class to the occupational subtrees (the `archetypeAxis` placement targets).

9. **Two distinct same-class principle individuals lose an edge.** `app/services/extraction/rpo_edges.py`, `collapse_same_class_principle_edges` (line 281). A duty legitimately derived from two individuals of one principle class keeps one edge (Board-invoked, else the hint, else the highest confidence). The commit message frames the pair as a merge signal, which D-10 supports for case 8; the rule reaches every case. Reported as a choice.

10. **A general type recurs against every specialization.** `app/services/defeasibility_view_service.py`, `_types_related` (line 370). A band row whose stored type is a general intermediate class (ProfessionalObligation) now relates to every class below it (ranks 5 and 6). In the intermediate tier only FaithfulAgentObligation chains through such a parent; the extended tier could not be inspected here.

11. **The ObjectivityObligation flag of section 6.2 could not be checked.** The extended tier lives in the OntServe database only. The archetype gate (`class_commit.py`, `_archetype_axis_conflict`, line 325) covers the states axis; the intermediate tier carries no class with two archetype parents on any of the nine axes (checked with rdflib against `CATEGORY_TO_ONTOLOGY_IRI`). The statement in 6.2 stands as the branch report made it: the gate changes what an existing state class accumulates on a re-discovery under another archetype.

12. **`PROETHICA_MATCH_LINK_THRESHOLD` is documented in `match_policy.py` only.** `.env.example` lists no `PROETHICA_*` variable, so the omission is consistent with the file; a commented line could join the next change of that file.

13. **Refresh-only mode has no production caller.** `defeasibility_pipeline.py`, `apply_defeasibility_edges` (`replace_prior`, line 384). Every commit runs the default replace through `materialize_edges_on_ttl`; the `stale_derivations` status is reachable from scripts only.

### Checked and found consistent

- The merged gate (`verification_gate.py` line 76) skips linked verbatim rows before the grounding call, keeps the quote snapping of prompts-and-filters (`_snapped`), cascades over judged and skipped rows, and reports `skipped` beside `snapped`; the commit task tags skipped rows vetted and never re-grounds them (`pipeline_tasks.py` lines 1346 to 1395). "Unchanged quotes" in section 6.2 means every quote already a token-level span of the case.
- `_record_edge_provenance._count` (`ontserve_commit_service.py` line 138) reads `triples_added` first. The defeasibility and R-P-O families report it; the provision families report `edges_added`; the edge_spec and causal families report `total`; state_edges reports per-property counts and counted as None before and after.
- `_ensure_definition` (`ttl_emitters.py` line 635) runs after every type-specific handler, keeps an existing `skos:definition` or `rdfs:comment`, prefers the row definition, writes back composed text only, and the content hash computed at publish includes it. The two golden fixtures gained exactly the three definitions the branch named.
- Both writers skip the type and the local declaration of a rejected class only when no shared tier establishes it; refused individuals stay unpublished and are listed under `refused_unpublished_type`.
- The matcher's cross-category gate (`matching.py`, `_reject_cross_category_match`, line 163) rejects a match whose chain category conflicts before storage, so the chain check that `_matched_class_override` skips for an already-typed row is applied upstream for every new row.
- `remove_defeasibility_layer` removes every competesWith, prevailsOver and defeasibleUnder triple of the case graph; the defeasibility pipeline is the only writer of the three predicates (grep over `app/`), so the replace is exact. A zero-edge run leaves the graph untouched and reports `reflects_active_record` false.
- `_derived_from_principle_hints` returns an empty map outside an app context, `resolve_principle_hint` runs only with a hint, and the collapse groups by predicate, subject and class while keeping edge order.
- The allow-list form of `_role_relationships_block` kept at the prompts-and-filters merge satisfies `test_vocabulary_block_lists_owes_duty_toward`.
- The new import of `match_policy` in `extraction_graph.py` introduces no cycle (`match_policy` depends on `entity_matcher`, which imports the standard library only).
- `_intermediate_graph` tolerates the missing extended file; the band fixtures pin an empty graph and the chain tests inject fixture tiers.
